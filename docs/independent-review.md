# 毎回の独立レビューは、現在の事実とユーザーの方向性から始める

2026-10-10〜11に確認したユーザーの意向は、レビューのたびに過去会話から離れ、その時点のChatGPTの判断を受け取ることです。目的・生活制約・本人が選んだ嗜好条件は固定し、その範囲で承認済みの配分内部や銘柄も必要なら見直し提案を認めます。判断の揺らぎを定期的な検討の刺激として受け入れ、同じ結論の再現を目標にしません。実行頻度や自動通知は、この設計では設定しません。

## Codexの内部確認とChatGPTへの入力を分ける

Codexは家計・口座・現行戦略・計画・取引を確認し、入力の欠損や具体的な未反映イベントを検出します。独立ChatGPTへ渡すのは、現在のスナップショット、現在有効な家計・口座・積立の観測事実、ユーザー自身の目的・生活制約・趣味の意向です。

現行戦略からは目的と定性的な意向だけを選びます。本人が選んだ数値を含む嗜好条件は、`financial/current.yaml`が指す`strategic_profile.objective_configuration.objective_models.maximize_terminal_wealth.lifestyle_constraints`から別途引き継ぎます。以前に承認された戦略配分・銘柄・上限、過去の投資仮説、レビュー、実行計画、タスクID・進捗、売却済み銘柄の一覧、候補注文、Codexの警告や評価を送りません。現在保有している商品名はスナップショットの事実として送ります。以前の推奨理由は添えません。

家計の金額、住宅ローン、生活防衛資金、確定支出、口座区分、取得費・含み損益は判断に必要な現在の事実です。現状の積立設定は観測事実として送り、今後も同じ額を拠出すべきという結論にはしません。記録上の未知はnullのまま残し、個人情報を推測で補いません。

既存注文・受渡・税務が判断を実際に変える場合は、Codexが根拠を確認し、その影響だけを現在の入力事実へ整理します。過去の台帳や計画を丸ごと渡す方法で代用しません。確認済みイベントを伏せることと、履歴を省くことを混同しないでください。根拠のない注文可能性を現在のブロッカーにもしません。

元パス、安定ID、確認日は由来を追うために残します。ChatGPTがそのファイルを開けることは前提にしません。独立レビューへの必須情報は本文へ埋め込み、ローカルファイルは配布媒体とします。

## 調査の進め方はレビュワーに委ねる

プロンプトは目的、必要な根拠、完了条件を示します。初回はレビュワーが重要だと判断する一論点だけを調べます。各回は結論・確認済み事実と直接URL・現状維持対変更の比較材料・未確認事項の判断への影響・次に送る短い指示を簡潔に返し、ユーザーが次を依頼するまで進みません。

銘柄の調査順、候補数・グリッド、特定の計算手法、モンテカルロや固定乱数シード、7セクションの回答、巨大な回答YAMLスキーマは強制しません。分析方法や分量は論点に応じて選べます。必要な仮定と計算限界は明示させます。意図的に違う結論を出すことや、新奇性を優先することも求めません。

工程の詳細と品質ゲートの生成元は[`prompts/workflows/independent_review.md`](../prompts/workflows/independent_review.md)です。テンプレートへ本文を埋め込み、次の責務を欠落させません。各工程は別の明示依頼で進めます。

| 工程 | 入力 | 出力・完了条件 |
| --- | --- | --- |
| 調査 | 現在の事実と一次情報 | 一論点の比較材料、反対材料、未確認事項の影響 |
| 証拠の充足判定 | 比較材料と不足情報 | 判断できる範囲、条件付きで進める範囲、重要な不足だけの再調査依頼 |
| 投資判断・行動設計 | 充足判定済みの材料 | 合理的な推論で一案を選び、行動・時期・条件・数量等の具体化可能範囲を示し、品質ゲートを確認 |
| 統合 | 判断済みの推奨・推論・条件 | 全明細へ展開し、判断との一致・意思決定価値を確認。漏れは判断工程へ戻す |
| Codex文書化 | 品質確認済みの統合結果 | 根拠を含む自己完結した反映依頼。未承認提案・未解決を保持 |

調査の終了は論点数で決めません。不足が推奨を実質的に変えるか、追加確認の価値が待つ費用を上回るか、条件付き推奨が可能かで判断します。未確認の解消だけを目的に調査を続けません。

「追加調査をしない」と「確認済み事実から推論しない」は異なります。投資判断工程では合理的な推論と明示した条件付き分析を行います。統合工程では新たな投資判断をせず、判断済みの推論も保存します。判断工程が未実施なら統合を完成扱いにしません。

各明細を具体化できる提案・条件付き提案・合理的な維持・判断保留に分けます。未知の税額や数量と、判断自体の不足を区別し、nullには影響範囲・理由・確認担当と方法・必要時期・結果別の行動を添えます。不要な注文項目は対象外とし、未知を装いません。根拠がある維持は正当な結論ですが、比較なしの暫定維持を一案の選択とみなしません。

全売買可能明細と新規購入について、維持対変更の比較、積極的な保有・変更理由、行動時期、次の操作を品質ゲートで確認します。保留やnullが大半なら該当する全件を再点検します。売却件数やnull削減のノルマは設けず、根拠ある保留は許容します。不足が残る範囲と解決方法を示し、形式的な網羅だけでは完了としません。

## レビューの自由度と運用の承認を分ける

本人が指定したサテライト比率は計画前提として尊重し、その内部の銘柄、集中リスク、相関・重複、税・費用、移行方法を評価します。毎回、全世界株式のみの基準案と比較し、比率自体への独立した客観的評価も簡潔に示します。結論は肯定・否定に固定せず、不利という評価だけで本人の嗜好を変更しません。特定銘柄の保有・売買の承認や、厳密な日次リバランス・自動売買トリガーには読み替えません。

新しい嗜好は過去の戦略の`purpose.enjoyment_preference`に優先します。戦略の運用配分・リスク上限・既存計画は今回変更しません。本人の「投資資産」と既存戦略の分母との対応、測定タイミング、許容変動幅は確認済み定義を確認し、今回の嗜好に未確認の部分は過去の運用レンジや推測で埋めません。

配分・銘柄・上限の再提案を認めても、既存の戦略・計画を自動的に無効にはしません。提案をユーザーが承認し、Codexが正本へ反映するまでは現行方針が運用上の正本です。0円と承認済みの戦術的待機資金を未設定扱いに戻したり、下落待ち資金の使用比較を機械的に義務化したりしません。

回答受領後、Codexが現行方針、既存タスク、取引台帳、年次税務、証券会社の注文仕様を照合します。構造化が必要ならリポジトリのスキーマへ変換し、YAML parse、schema validation、重複ID、参照整合性、関連テスト、repository-auditを実施します。未確定値をゼロ埋めせず、未承認提案を注文可能・実行済みと扱いません。

## 数値の正確さと判断の合理性を別々に確かめる

- 目標・目安・制約・絶対下限を区別します。生活防衛資金の目標を厳密な残高下限へ変換せず、ストックとフロー、給与振込・カード引落等の通常変動と構造的不足を分けます。スナップショットだけで問題を認定せず、経済的重要性を評価してから対策を比較し、何もしない選択肢も残します。
- ユーザーの目的・制約・嗜好の階層を保ちます。局所的な数値改善をユーザー効用の改善と同一視せず、税・費用・機会損失・生活への影響、本人が重視する非金銭的価値を考慮します。
- 確認済み事実・推論・仮定・推奨・未確認事項を分けます。仮定上の最適値を実証済みの最適値にせず、数量・価格・期限には根拠を添えます。未確認を推測で埋めず、未承認提案を確定戦略・注文計画へ昇格させません。
- 比率の分子・分母・測定時点を明示し、異なる基準日の価格・数量・評価額を混ぜません。比較案は拠出・税・費用・評価時点を統一し、条件付き試算と将来予測を区別します。計算の正しさとは別に問題設定・比較前提と差の重要性を検証します。
- 投資判断工程は確認済み事実と明示した条件付き推論に基づいて一案を選びます。統合はその判断・推論・条件と未確認事項を保持し、不整合を追加調査や根拠のない再判断で補いません。各工程の目的・入力・出力・完了条件を守り、次工程はユーザーの明示依頼を待ちます。
- 人間が確認しやすい簡潔な成果物を実際に返します。内部処理完了と提示を区別し、確認できない画面状態や不具合原因を断定しません。表示不具合を指摘されたら再提示を優先します。独立セッションへの引き継ぎは必要情報を本文に含め、ローカルファイルや過去会話へのアクセスを仮定しません。

## 共通の生成経路

`generate-review-prompt`を標準とし、`monthly-run`は同じ処理の互換名にします。`prompts/templates/independent_review_template.md`、`prompts/workflows/independent_review.md`、`src/monthly_limit_order_review/independent_review.py`を使用し、市場調査・旧計画からの保有数量投影・候補注文生成を経由しません。毎回新しい出力ディレクトリへ依頼・入力・状態説明・生成元のSHA-256を持つ`generation_manifest.yaml`を保存します。

`monthly_review_template.md`、従来のReviewPacket・回答スキーマ、`on-demand-decision-prompt`は過去回答の再現・検証用の互換機能として残します。包括レビューの新規依頼には使用しません。ヘルスチェックは補助調査として維持し、その結果を次の独立レビューへ自動注入しません。

検証では入力の正確さ、除外対象の混入、口座ゲート、自己完結性、出力先・履歴保護に加え、工程の順序・判断の責務・不足情報の分類・品質ゲートを確認します。同じ投資結論になることはテストしません。実行失敗の保存・評価方法と自動検証の限界は[品質評価](independent-review-quality.md)を参照してください。

設計上の参考：OpenAI公式の[Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)は、簡潔で直接的な指示を推奨しています（2026-10-10確認、随時更新される文書）。今回の自由度・入力範囲は、上記のユーザー意向に基づくものです。
